## Findings / triage

- [P0] A blind 1.4 open changes old SQLite sessions irreversibly for 1.3.
  - Evidence: upstream 1.4.0 changelog: opening migrates task table to schema v2, and 1.3 cannot open it; local runtime.ts calls Harness.open/resume through normal session startup.
  - Impact: rollback of only plugin binaries cannot recover an already migrated session; restoring a snapshot can lose post-snapshot writes.
  - Rule: AP-013, AP-033, AP-034, AP-061.
  - Fix decision: blocked — copied-session test/restore proof and explicit production admission before any original open. Addressed in master G-LOCAL and U2/U4, not executed.

- [P0] Marketplace/Git -> local source is not a harmless per-thread install.
  - Evidence: BB plugin-registration.ts:296–321 refuses source replacement without removal; plugin-service.ts:1267–1281,1721–1767 deletes settings, secrets and schedules on removal. Installed source is shared provider-pi-durable v0.2.52; user says all threads depend on it.
  - Impact: provider availability and state for the whole installation, including the current control thread, can be interrupted or lost.
  - Rule: AP-013, AP-027, AP-034, AP-042, AP-061.
  - Fix decision: blocked — do not run uninstall/install/dev/reload. Prove supported state recovery in disposable state, preserve configuration/KV/bindings/protected state, use external control terminal and obtain recoverability-card consent.

- [P1] The current adapter is not 1.4-compatible by changing package pins alone.
  - Evidence: src/runner/subagent-delivery.ts gather calls runtime.sleep; reporter checks only pending/running/waiting; adapter-owned defineDoc calls have no checkpointWhen. All are affected by published 1.4 changes.
  - Impact: startup/API failure or duplicate sleeping courier/report delivery.
  - Rule: AP-012, AP-023, AP-028, AP-033, AP-035, AP-050.
  - Fix decision: fix-now in authorized U1.2 slice — explicit checkpoint policy, sleepUntil phase transition and non-terminal liveness test. Not fixed by planning.

- [P1] Existing warm runner reuse is not proof of new runtime execution.
  - Evidence: src/host/session-registry.ts createOrGet returns a live existing session; session-storage.ts can evict a live owner on collision; current identity response is not a build-level admission contract.
  - Impact: a user sees an updated plugin but continues on old code, or a forced probe kills ongoing work; root/child aliases complicate safe restart.
  - Rule: AP-013, AP-026, AP-034, AP-038, AP-048, AP-059.
  - Fix decision: fix-now in U3 after baseline is selected. Require actual runner identity and serialized boundary; no guarantee of transparent active-turn transfer.

- [P1] Current planSteps projection loses lifecycle meaning and outcome evidence.
  - Evidence: task-graph-bridge.ts maps waiting to pending, completing outcome to final-looking completed/failed, and evicted non-failed knownSteps to completed; tool.js can settle TaskOutcome completed with result.isError true.
  - Impact: informative-looking UI reports false success or confuses expected tool error with runtime failure.
  - Rule: AP-013, AP-026, AP-049, AP-050.
  - Fix decision: fix-now in G1/G2 with separate native status, authoritative terminal receipt, result-error badge and typed observation errors.

- [P1] A graph UI is not yet authorized under the project-owned no-custom-UI instruction.
  - Evidence: AGENTS.md explicitly forbids inventing UI components. BB slots accept plugin components; their existence is not a policy exception.
  - Impact: silently implementing a custom renderer violates the agreed thin-adapter boundary.
  - Rule: AP-010, AP-020 and local AGENTS.md.
  - Fix decision: blocked — request narrow explicit UI-policy clarification before G3. Do not edit governing instructions as part of plan preparation.

- [P2] The development baseline contains concurrent feature work and pre-existing file budget pressure.
  - Evidence: inspected HEAD 4ba97b0; seven commits ahead of origin; dirty subagent-policy plan/review files; session.ts 240 lines and app.tsx 249 at inspection, while touched TS policy is <200.
  - Impact: installing or pushing this checkout can unintentionally deploy unrelated work; large shared composition roots amplify conflicts.
  - Rule: AP-011, AP-019, AP-025, AP-046.
  - Fix decision: blocked for baseline selection; fix-now only narrow touched-file extraction during relevant slices. Never include another thread's dirty files or publish unrelated ahead commits in this task.

- [P2] A graph packet has to cross real BB process/store boundaries.
  - Evidence: public SDK extension.state + provider extensionKinds.state + thread/extensionState/updated + threads.events.list/realtime; provider bridge and host-RPC singleton sharing is not an established contract.
  - Impact: an in-memory graph in the wrong worker can yield a blank UI or stale state after restart; unbounded snapshots can inflate event storage.
  - Rule: AP-026, AP-028, AP-032, AP-038, AP-045, AP-055.
  - Fix decision: fix-now in G2 seam proof using native extension.state, scoped public reads and measured bounded publication. Stop if the actual public event/realtime round-trip fails.
