Remove the plugin and install it again to accept the new commit` (`outcome: "unavailable"`).

## 5. Old sessions — expected behavior and proof required

Expected user journey, not an untested guarantee:

1. Thread remains the same BB thread and provider identity; previous messages/checkpoints/bindings stay addressable.
2. A new 1.4 runner opens the same native session, migrates it once, and reads its existing transcript/documents.
3. Old terminal entries remain; pending work follows upstream recovery; unsafe interrupted tools are not promised transparent re-execution.
4. The next user input is admitted exactly once by the new runner, not silently handled by an old process.
5. Remaining idle sessions are migrated only when actually reopened; no all-session eager migration.

Adapter acceptance covers root/child reconnect, generation/tool outcomes, courier/report/hold, bindings and policy ACK through ordinary public-surface tests. Synthetic migration/rollback rehearsal is removed from this plan; do not expand it or treat it as a prerequisite.

A plugin source switch does not itself change the SQLite schema. Opening a session with 1.4 does. Schema v2 cannot be reopened by 1.3. A pre-upgrade snapshot can restore the old state, not magically preserve later 1.4 writes; preserve failed/new state separately and obtain approval before any destructive restore.

## 6. Gate G-LOCAL — global blast radius and source-change blocker

The user states all their threads use this plugin. A local install of the SAME plugin/provider ID replaces the provider for this BB installation; it is not per-thread isolation.

## 8. Graph acceptance contract

- Actual task lifecycle and phases only: pending/running/waiting/sleeping/completing/terminal; blocked reason is metadata, not an invented TaskState.
- Preserve all terminal outcomes: completed/failed/aborted/faulted/orphaned.
- Distinguish completed task + tool result `isError` from failed task.
- Owner edges and wait edges are different; conversation history parent is not execution owner.
- Native child ownership remains stable after an anchor becomes terminal.
- Missing/deleted live node means receipt must be reconciled, not automatic success.
- Expose background/abort request as badges, not fake terminal states.
- Connection/runner readiness is separate from task state. Old snapshot cannot keep pretending to be live.
- No progress percentages, inferred human phases, model-generated graph JSON, fake phase timing or new scheduler.
- Active tree in context segment; stable selection/scroll; optional time bars with labelled lifetime; true tool execution duration separate; one bounded inspector; keyboard/reduced motion/theme support.
- v1 scope: live graph + explicitly bounded recent authoritative results; not a complete persisted phase timeline or semantic project plan. Message embeds are deferred, not an implicit extra feature.
