# Durable 1.4 — упрощённый ручной переход и аварийный промпт

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for the bounded code adaptation. This is a proposed operator-assisted route; it does not report a completed upgrade or authorize switching the provider during an active turn.

**Goal:** Подготовить рабочий локальный плагин 1.4, дать Ване вручную остановить работу и подключить сборку, затем продолжить проверку в существующем треде.

**Architecture:** Холодное переключение после остановки работы вместо сложного live-handoff. Native Antigravity — независимый аварийный исполнитель, не механизм восстановления утраченных данных.

**Tech Stack:** Existing BB plugin, exact Pi ecosystem 1.4.0, native Antigravity for recovery.

## Приоритет над первоначальным планом

2026-10-25 Ваня предложил упростить переход: он готов вручную дождаться остановки всех тредов, подготовить/подключить локальную версию и вернуться сюда для проверки. Резервные копии не входят в запрошенный упрощённый маршрут. [Source: User, BB thread thr_ct3kk9xne6]

Для этого маршрута требования исходного master-плана об обязательных backup/restore rehearsal, отдельном копировании реальных сессий и автоматическом live-handoff не являются предварительными условиями. Они остаются описанием более защищённого альтернативного rollout. Не объявлять их выполненными и не создавать копии вопреки пожеланию пользователя.

Сохраняются: исправление настоящих API-несовместимостей 1.4, обычные детерминированные тесты на искусственных данных, корректный выбор локального источника, запрет удаления/сброса пользовательских данных, UI-policy gate, точность lifecycle, запрет публикации marketplace до проверки.

Это НЕ гарантия безрискового перехода: после миграции оригинальной SQLite в 1.4 библиотека 1.3 её не откроет. Без копии нельзя обещать простой откат или восстановление потерянных/перезаписанных данных. Диагностический доступ через Antigravity эту границу не отменяет.

## Минимальный рабочий порядок

1. **Подготовка до переключения.** Довести код адаптера и его локальные зависимости до coherent 1.4.0; исправить удалённый runtime.sleep, sleeping courier dedup и обязательный checkpointWhen. Собрать и прогнать обычные тесты. Пока не менять установленный provider и не открывать оригинальные сессии новым Harness.
2. **Ручная пауза.** Ваня дожидается завершения/останавливает root и фоновых субагентов. Проверить, что работа не продолжается. `idle` в BB не означает, что сам runner process завершён: SessionRegistry сохраняет живую сессию. Перед загрузкой новой сборки старые runner/host worker должны быть штатно завершены; не убивать все процессы node.
3. **Подключение локальной сборки.** Подключить именно подготовленный plugin source. Глобальное обновление `pi`/npm не обновляет зависимости уже установленного Git-cache плагина: его runner импортирует внешние Pi-пакеты из собственного package tree. Глобальный CLI можно обновить отдельно, но это не замена шагу 1.
4. **Ручной source-switch — не скрытая операция.** В проверенной BB Git→path для того же plugin ID требует remove first; remove удаляет настройки/секреты/расписания. Этот шаг не автоматизировать без принятия конкретных последствий пользователем. Не подменять строку plugins в BB DB и не предлагать uninstall как безвредную команду. Если пользователь хочет сохранить всё и публичный способ этого не найден — сообщить ограничение, не выдумывать обход.
5. **Возврат в существующий тред.** Первый новый runner открывает ту же native session; upstream миграция выполняется при открытии. Проверить старую историю/идентичность/модель, фактический локальный runner path и его версию, один новый ответ без дублирования. Не мигрировать все остальные сессии заранее.
6. **Дальнейшая работа.** Здесь продолжить проверку/исправления и затем runtime graph. Публикация/тег/marketplace не выполняются автоматически.

## Проверенные основания

- `scripts/build-runner.mjs`: Pi libraries external; module resolution belongs to выбранному plugin tree.
- `src/host/{runner-process,session,session-registry,paths}.ts`: runner lifetime, source lookup and native session paths.
- Upstream 1.4.0 changelog: schema-v2/no 1.3 downgrade, sleepUntil and explicit checkpointWhen.
- BB public install/remove commands and source-map registration/removal originals: source guard and state deletion.
